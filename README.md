# Safety Check Pro (41)

Ты — Senior Frontend-разработчик. Твоя задача: создать PWA (Progressive Web App) для самопроверки знаний сотрудников по технике безопасности. Пользователь: рядовой сотрудник предприятия (рабочий склада, цеха, ИТР). Задача пользователя: за 5 минут ответить на серию вопросов, чтобы подтвердить знание инструктажа. Моя цель как заказчика: получить работающее веб-приложение с админ-панелью, которое можно открыть по ссылке в браузере на любом устройстве.

Сценарий использования (Happy Path)

Сотрудник открывает ссылку на тест.

Видит экран приветствия с правилами и кнопкой «Начать проверку».

Отвечает на вопросы один за другим.

При ошибке система не дает идти дальше, пока ответ не станет верным.

После ответа на последний вопрос или по истечении времени видит финальный экран.

Данные о прохождении улетают руководителю.

Экраны приложения Экран 1: Приветствие (/) Компоненты: заголовок («Проверка знаний по ТБ»), краткий текст правил («Вам будет предложено N вопросов из M. Время на прохождение: 5 минут. Вы не сможете перейти к следующему вопросу, пока не ответите верно на текущий»), кнопка «Начать проверку». Поле ввода табельного номера (обязательное). Экран 2: Прохождение теста (/test) Компоненты: индикатор прогресса (например, «Вопрос 3 из 10»), таймер обратного отсчета красного цвета (MM:SS), текст вопроса, кнопки-радио с вариантами ответов, кнопка «Подтвердить ответ» (деактивирована, пока не выбран вариант). Никаких хлебных крошек и шапок сайта — только контент теста. Экран 3: Ошибка (модальное окно поверх /test) Текст: «Ответ неверный. Ознакомьтесь с вопросом еще раз и выберите правильный вариант». Кнопка «ОК», которая закрывает модалку и возвращает фокус на выбор ответа. Экран 4: Успех (/success) Заголовок «Проверка пройдена успешно!», подзаголовок со статистикой (время, количество попыток на сложные вопросы), крупная зеленая иконка-галочка, кнопка «Завершить / Закрыть вкладку». Экран 5: Время вышло (/timeout) Заголовок «Время вышло», статистика (сколько успели ответить), красная рамка, кнопка «Попробовать еще раз» (сбрасывает сессию). Экран 6: Админ-панель (/admin) Простейшая таблица с колонками: Дата/Время (ISO), Табельный номер, Результат (Пройдено/Провалено/Таймаут), Балл (X/Y), Ссылка «Подробнее». По клику на «Подробнее» раскрывается список ID вопросов, где была допущена ошибка.

Данные и структура базы (Local Backend) Таблица questions.json (или база данных): id, category (общие / профильные), text (текст вопроса), options (массив строк), correct_id (ID правильного варианта), is_critical (boolean), explanation (текст-подсказка "Почему это важно", показывается после ошибки). Таблица results: id, employee_id (табельный номер из формы), timestamp, score (верно/всего), duration_sec, failed_questions (массив ID), status. Контекст сессии (State): текущие 10 случайных вопросов, индекс текущего вопроса, счетчик правильных, массив истории ответов.

Поведение и логика (Backend Logic)

Старт: при нажатии «Начать» приложение проверяет заполненность табельного номера, берет из базы 10 случайных вопросов (гарантируя наличие минимум 2 критических), сбрасывает таймер.

Отображение: варианты ответов перемешиваются при каждом рендере вопроса.

Валидация: пользователь выбирает вариант, активируется кнопка подтверждения. При нажатии:

Если верно: звук успеха (короткий 'ding'), +1 к счету, авто-переход к следующему через 500 мс.

Если неверно: звук ошибки ('buzz'), появляется Экран 3 (модалка). После закрытия модалки выбранный неправильный радиобаттон становится неактивным (disabled), остальные остаются кликабельными.

Критические вопросы: если вопрос помечен как is_critical: true, цикл «ошибка → новый выбор» повторяется бесконечно, пока не будет дан верный ответ.

Финал: тест завершается досрочно, если отвечены все вопросы, либо принудительно по таймеру.

Отправка: результат POST-запросом уходит в базу. В бесплатной версии Lovable данные пишутся в Supabase (настрой таблицу заранее) или имитируются выводом JSON на экран успеха.

Лимиты: одна IP-сессия = одна попытка в 5 минут. Повторный клик «Начать» до истечения таймера выдает предупреждение.

Дизайн и UX (UI Specification) Технологии: React (Vite) + TypeScript + Tailwind CSS. Библиотеки: Framer Motion (для плавного появления вопросов), SweetAlert2 или Radix UI (для модалок). Цвета: строгий корпоративный стиль. Фон #F5F7FA. Основной текст #1A202C. Акцентный цвет — зеленый (#2ECC71) для успеха, красный (#E74C3C) для ошибок и таймера. Типографика: системные шрифты (без внешних подключений для скорости). Заголовки полужирные, размер текста комфортный для чтения с экрана смартфона (минимум 16px). Адаптивность: резиновая верстка. Поля по краям 16px, максимальная ширина контейнера 500px по центру. Элементы крупные (закон Фиттса), чтобы легко попадать пальцем в перчатке. Микровзаимодействия: легкая вибрация телефона (API Vibration) при ошибке; подсветка правильного ответа мягким зеленым свечением.

Критерии готовности (Acceptance Criteria)

Приложение открывается по прямой ссылке в Chrome/Safari на ПК и смартфоне без установки.

На экране приветствия поле табельного номера нельзя пропустить пустым.

Таймер начинает обратный отсчет ровно с 05:00 только после первого клика по варианту ответа.

Невозможно нажать кнопку подтверждения без выбора варианта.

При выборе неправильного ответа переход блокируется, пока пользователь не выберет правильный (реализован механизм блокировки прошлых неверных вариантов).

Критический вопрос невозможно пройти «мимо»: тест висит на нем до победного.

Варианты ответов внутри каждого вопроса всегда расположены в новом случайном порядке.

В базе данных (Supabase) создается новая запись с табельным номером, временем, результатом и списком неверных вопросов.

Админ-панель корректно отображает последние 50 записей таблицы результатов.

Код написан на TypeScript, компоненты разделены (WelcomeScreen, QuestionCard, AdminTable).
